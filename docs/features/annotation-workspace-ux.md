# 标注工作台交互与布局方案

状态：已按用户确认的 HTML 效果图实现，并通过自动回归与独立复审；2026-09-09。视觉依据为 `docs/previews/annotation-workspace/workspace-{1366,1920}.png`，不保留预览专用标记及模拟保存信息。人工手感验收待用户测试。

## 需求定义与边界

本提案以用户提供的当前精修截图、现有工作区代码，以及“Initialize 后精修并连续标注”的既有需求作为 Concept Brief 等价输入。

- 用户：使用桌面鼠标和键盘、连续处理本地大量图片的标注员。
- 核心任务：初始化五官轮廓，整体对齐，局部精修，确认保存，继续下一张。
- 核心问题：加点与选择/拖动冲突，删点的目标和曲线结果不够可预测；常用工具埋在长侧栏里，标签与对象的视觉表达混淆。
- 目标：普通选择不修改几何；点编辑不误删整条轮廓；常用操作在桌面视口中固定可见。
- 保留：Initialize、手绘、整体变换、局部重画、可选柔性编辑、右键平移、撤销重做、现有文件夹/浏览器保存流程和品牌配色。
- 非目标：重新设计项目首页、增加 AI、改存储格式、迁移用户标注、限制每种标签只能有一条轮廓、部署或提交代码。
- 假设：桌面优先，1366×768 与 1920×1080 是拟验收尺寸；不是对用户实际屏幕的测量。方案说明使用中文，不等于本次决定将整个应用翻译为中文。

## 证据与限制

用户截图：`C:/Users/Admin/AppData/Local/Temp/codex-clipboard-c5a811cb-b736-40ac-82fb-ffbb58736d29.png`。

这是基于用户截图、只读源码检查和纯函数复现的设计评估，不是对用户活跃浏览器的完整操作测试。

1. `src/app.js` 的 `handleRefinePointerDown`：Points 工具中，已选中轮廓的 edge 命中直接调用 `insertCurvePoint`，发生在 pointerdown，尚未区分普通点击与拖动。误操作风险成立；不能仅根据截图的 28/30 点断言所有新增点都是误触。
2. `deleteSelectedPoint` 删除后清空 `selectedPoint`，而全局 Delete/Backspace 分支在没有选中点时调用 `deleteSelected`。因此连续删除存在从删点升级到删整条轮廓的路径。
3. `src/contour-editing.js` 的 `deleteCurvePoint` 直接拼接相邻段的部分控制点。只读复现：端点 (100,100)、(300,100)，控制点 (100,300)、(300,300) 的曲线，在 t=0.5 插点后立即删除该点，中点从 (200,250) 变成 (200,175)。不是对用户图片数据的修改，也不能据此量化截图中轮廓的误差。
4. `index.html` 左栏固定项目/保存区和整轮廓删除区，但精修、翻图、Initialize 都在滚动区。截图滚到标签后，精修和翻图工具不可见。
5. 左侧标签用于新建，右侧轮廓代表现有对象；逻辑并非重复，视觉却相似。截图左侧 face outline 与右侧 right eye 同时高亮，操作目标不清。
6. 原桌面列宽为 292px + 画布 + 352px；右侧每项常驻下拉框、删除、点数和尺寸，低频信息持续占用画布空间。

布局规则扫描没有报告机械违规；这不能证明信息层级或操作效率合理。当前方案未完成响应式、键盘或辅助技术的实机验证。

## 竞品参考

- [Labelme 官方更新记录](https://github.com/wkentaro/labelme/blob/main/CHANGELOG.md)：记录 Alt+Click 加点、Alt+Shift+Click 删点，以及右键 Add Point to Edge。依据是官方记录，不代表本轮实测所有发布版本。
- [CVAT polygon 编辑文档](https://docs.cvat.ai/docs/manual/advanced/annotation-with-polygons/edit-polygon/)：Shift+点击进入局部重画，用新路径连接原轮廓，并可取消或选择保留部分。

结论：点击/拖动作为定位手段正常，但绘制、选择、移动、插点和删除应有不同且明确的意图。竞品快捷键不是本项目必须复制的标准；本项目继续保留右键拖动画布，不能直接用同一手势打开删除菜单。

## 统一语言

| 术语 | 含义与界面约束 |
| --- | --- |
| 轮廓 / Contour | 已存在的可编辑对象；允许相同标签对应多个对象。 |
| 标签 / Label | 新建对象的类型，或当前对象的属性；不是另一份对象列表。 |
| 点 / Point | 可编辑锚点，不是导出折线的采样点。 |
| 调点 / Edit points | 移动已有点、显式插点和删点；不改变删除目标到整条轮廓。 |
| 整体 / Transform | 整条轮廓的移动、缩放与旋转。 |
| 已保存 / Saved | 当前修改已完成所选存储后端的保存，不等于图片已被标记 Done。 |

## 推荐布局

采用“顶部固定工具 + 中央画布 + 单一右侧对象栏 + 底部固定任务操作”。保持当前浅色面板与绿色选中状态，不更换整体视觉风格。

```text
项目栏：退出 | 项目 / 当前文件                         已保存 | 文件 / 更多
工具栏：Initialize | 调点 | 整体 | 局部重画 | 新建      撤销 / 重做 | 缩放 / Fit
情境行：当前轮廓、加点/删点；或新建标签；或重画确认操作（按当前工具显示）
┌────────────────────── 画布 ─────────────────────┬── 轮廓 ────────────┐
│                                                 │ 右眼 · 28 点       │
│                                                 │ 左眼 · 30 点       │
│                                                 │ 眉毛、鼻子、嘴…    │
│                                                 │ 当前对象的属性     │
└─────────────────────────────────────────────────┴────────────────────┘
任务栏：图片队列 | 上一张 | 下一张 | 1 / 1915       跳过 | 待复核 | 完成
```

- 删除左侧独立的长标签面板。右侧对象使用紧凑单行；只有选中对象展开属性，不为每条轮廓常驻编辑表单和红色删除按钮。
- 新建工具才显示标签及合法开闭类型。精修时始终显示当前对象名称，不出现另一种“准备新建标签”的高亮。
- Initialize 固定可见；沿用只补缺失模板等现有业务规则，不因移位覆盖已修改轮廓。初始化后进入精修上下文。
- 手动保存、输出路径、导入/下载 JSON 放文件菜单；保存失败时例外，固定展开原因、重试和下载当前 JSON，不能隐藏到菜单中。
- 图片队列按需抽屉展开，保留现有分页；关闭后回到触发按钮。翻图操作不依赖队列展开。
- 上一张、下一张、跳过、待复核、完成保留既有语义。本次不默默将 Done 改为自动跳图；“完成并下一张”可作为独立确认的小扩展。
- 右侧对象栏建议 240–280 CSS px，行高约 36–40px。1366×768 下不出现整页滚动，1920×1080 下让画布使用增加的空间。
- 更窄视口/浏览器放大时将右栏折叠为可访问抽屉，而非堆到画布下方。文件名截断可查看完整路径；常用工具和翻图入口不因截断消失。
- 锚点按屏幕像素保持可见和可命中的尺寸，选中点用轮廓/形状区分，不只依赖颜色；只显示当前轮廓的点，减少遮挡。

备选布局为窄左工具条 + 右侧对象栏：适合更多工具和熟练用户，但需要记图标，并仍占横向画布空间。本项目仅少量核心工具，推荐顶部方案；最终由用户确认，不同时叠加两套常驻工具区。

## 交互规则与对应验收

下列为本次实现的交互契约。

| ID | 触发与约束 | 允许/禁止与用户反馈 | 场景 |
| --- | --- | --- | --- |
| R1 | 调点工具普通点击轮廓/点 | 仅选中，不插点；选中名称与右侧列表一致。 | A1 |
| R2 | 拖已有点 | 只移动该点；默认不启用柔性影响，也不补点。整体变换只在明确的整体工具内提供。 | A1 |
| R3 | 在选中轮廓线上双击 | 推荐的免修饰键插点动作：插入一个点，突出新点且不改变原曲线；双击已有点不重复创建。不能在第一个 pointerdown 就写入。 | A2 |
| R4 | 不使用双击的标注员 | 情境行“加点”按钮启用一次性插点：显示候选位置，点线提交一次后返回调点；Esc 取消。状态必须可见，不变成隐蔽持久模式。 | A2 |
| R5 | 选中点后 Delete/Backspace 或“删除点” | 只删点，必须保留开线至少 2 点/闭线至少 3 点；没有选中点时不回退为删轮廓，重复按键不批量误删。 | A3 |
| R6 | 删除整条轮廓/清空 | 由明确写有目标的对象菜单触发，提供撤销；清空需明确确认。不能复用调点状态下的普通 Delete。 | A3 |
| R7 | 删除锚点后的几何 | 未编辑的可逆细分应恢复原段；一般删除需要局部拟合并给预览，保留其余段。不能承诺任意两段合一都完全保形；放弃时原数据不变，提交后可撤销。 | A4 |
| R8 | 切换对象/工具、结束重画 | 未确认的重画/删除预览先处理，不能静默丢弃或自动保存成最终轮廓。 | A5 |
| R9 | 保存、翻图、退出 | 沿用现有真实保存编排与失败保护；成功后才显示已保存，失败同处显示原因/重试/备份。 | A6 |
| R10 | 可访问性与密集点 | 鼠标之外保留可聚焦操作按钮；输入框内 Delete 不影响轮廓；候选点/当前点突出，重叠时确定性命中最近点。 | A3、A7 |

双击方案需要验证触控板/鼠标的舒适度，不宣称它天然优于所有修饰键方案。若用户更倾向 Labelme 的 Alt+Click，可在实现前改定主手势，不同时加入过多相似快捷键。

## 流程与数据模型

主流程：进入已有项目 → 当前图片 → Initialize（需要时）→ 选轮廓 → 整体对齐 → 调点或局部重画 → 确认已保存 → 标记完成并翻图。

替代流程：从新建工具选择标签绘制；从队列跳到另一图片；用文件菜单下载/恢复当前标注；异常时通过固定错误区重试或保留备份。

数据模型不变：项目、图片、轮廓及曲线契约保持不变；仅调整视图布局和短生命周期交互状态。删除保形的实现若确实需要持久化新元数据，必须先另行评估，不在布局改动中默认升级 JSON。局部拟合或预览只处理候选结果，确认后走现有撤销及保存通路。

不改变目录权限、原图只读、工作区占用保护和冲突检测。长路径、空轮廓、同标签多轮廓、大图片队列都必须可用；保存状态与业务 Done 状态继续独立。

## Acceptance Scenarios / 后续验证输入

- A1：Given 已选轮廓，When 单击轮廓线或拖现有点，Then 点数不增加，选择不改变曲线，拖点只产生一次可撤销编辑。
- A2：Given 合法曲线段，When 双击或一次性加点，Then 仅增加一个锚点且保形；双击已有点/取消加点不改数据。
- A3：Given 已选锚点，When 连续 Delete，Then 不删除整条轮廓或其他轮廓；达到最低点数时解释原因；表单输入和键盘长按不得绕过规则。
- A4：Given 同一段刚插入且未编辑的点，When 删除该点，Then 曲线恢复；一般删点先预览，取消不变，提交后 Undo 恢复原曲线。覆盖开线端点、闭线首尾点与密集点。
- A5：Given 待确认预览，When 切换对象/图片或退出，Then 不静默提交或丢弃，按照明确的确认/取消流程处理。
- A6：Given 真实文件夹或浏览器项目，When 编辑后保存/翻图/重开，Then 几何与保存状态一致；权限丢失、冲突、写入失败时恢复操作固定可见且原有安全边界不变。
- A7：Given 1366×768 或 1920×1080，When 连续完成主流程，Then 不滚动整页或工具栏寻找 Initialize、精修、撤销和翻图；只有对象/队列自身可滚动。检查浏览器缩放、窄视口、焦点返回、长路径和错误提示。

验证映射：A1/A2/A3/A5 使用真实前端事件和状态编排测试；A4 使用纯几何回归；A6 使用双保存后端的真实工作流测试；A7 使用上述尺寸的浏览器截图、DOM边界与焦点断言。自动验证已通过；设备手感、原生授权对话框仍需人工验收。

## 实现决策与不变量台账

只调整工作台结构、短期交互状态和局部删点算法。领域算法仍在 `src/contour-editing.js`，页面编排在 `src/app.js`，显示在 `src/renderer.js`。不修改项目首页、JSON schema、文件写入协议；不引入新框架。放弃仅用 CSS 隐藏旧侧栏：那会留下重复控制和不一致的操作目标。

| 不变量 | 权威数据源 | 锁/事务 | 内部接口投影 | 前端状态与恢复 | 验证 |
| --- | --- | --- | --- | --- | --- |

## Soft edit 点选索引修复（2026-09-09）

提交前复审发现：柔性编辑在 pointerdown 预备插入边界点时改变了点索引，但纯点击没有应用这份预备曲线。选中态提前使用预备索引，随后删除会命中原曲线中的邻点。用户已同意先修复此问题，颜色、点线尺寸和其他视觉建议不在本次修复范围内。

修复不变量：`selectedPoint.index` 始终对应当前 `state.contours`。未超过拖动阈值时使用原命中索引；实际应用预备曲线后，才切换为对应的新索引。无需新增持久化字段或改变几何算法。

Test Plan：在既有 `browser-contour-editing.test.mjs` 的真实 IndexedDB/文件夹 OPFS 双后端流程中补充以下场景；仅目录选择器是替换的外部边界，生产 pointer/save coordinator 不 mock。

| 场景 | 风险 | 断言 |
| --- | --- | --- |
| 开线内部点、末端点及闭线点的纯点击 | 边界/错误目标 | 不改变曲线；删点仅移除点击的锚点，预备索引越界也不能造成无法删除。 |
| 小于 2 CSS px 的微小移动 | 边界 | 不触发编辑；删除目标仍为原命中点。 |
| 删除预览取消、确认、Undo | 数据完整性 | 预览与取消不改几何/持久化；确认删除正确锚点；Undo 恢复原曲线。 |
| 真正的柔性拖动后直接删除 | 正常/状态转换 | 预备曲线应用后选中目标同步；删除已拖动锚点而非原索引处的其他点。 |
